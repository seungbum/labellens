\section{Ethical Use of Data}
\label{sec:ethics}
LabelLens reads only public data through public APIs and stores nothing about visitors. Queries go from the visitor's browser to Bluesky and the labelers, so each queried labeler learns the visitor's IP address and the inspected item; official clients avoid this because Bluesky's servers attach the labels a user subscribes to (the \texttt{atproto-accept-labelers} header~\cite{ATProto_labels}). LabelLens states this before the first query and offers a privacy mode that queries only Bluesky's labeler. The measurement replayed public label streams through each service's documented endpoint, one connection per service (twelve parallel ranges for the largest one), with an identifying user agent. We publish aggregate figures per labeling service only: no list of labelled accounts or posts, and the per-labeler table omits label values, which can describe a person (for example pronouns or political affiliation). For services without CORS, the public site ships collected labels only for its organisational example accounts, its build and a repository check refuse any other snapshot, and the venue demo runs this public build. The raw label logs were deleted after analysis. Labels can be wrong or hostile; showing one does not endorse it, and the interface says so. Examples in the interface and this paper use organisational accounts. No human participants were involved.
